## correctness

Traced: `runSummaryCommand` → `summaryFor` → `locateSlice` → `replayedSlices` →
`replayFinishedProcess`, plus `gtd slices` and `gtd history` on the same shared
path. Read-only commands: no writes, no saved ids, no retry path. One config
load now feeds both the template check and the replay (was two loads). The
empty-trace, missing-template and edited-config-dropped-summary orders match the
old behaviour, and tests cover them. The dropped `narrowToSlice` guard can no
longer be hit, because `locateSlice` builds the slice from the same `run` inside
the same call. No new mocks.

**Nit**

1. **The new doc comment says the warning comes "before any refusal". For two of
   the three `--slice` refusals it comes after.** (`src/cli/Program.ts:329-330`,
   `src/edge/Edge.ts:1724`)
   - **Problem:** Only the unknown-slice refusal prints the warning first,
     through `Narrator.warn`. The config-drift and divergence refusals put it
     inside the error itself, as `${err.message}\n${versionWarning}`. So it
     shows after the `refused —` line, and under `--json` it also lands in the
     error envelope's `prompt` field. The same thing now happens to
     `gtd history` refusals. `docs/cli.md` L430-434 calls the warning its own
     stderr line, separate from the message.
   - **Fix:** Make the comment true. Either say "the unknown-slice refusal
     prints the warning first; a replay refusal carries it in its message", or
     raise a `GtdError` whose `detail` holds the warning line, so it is kept
     apart from the message. Deferred note-1 (eda53bb) already reopens this
     comment, so the fix can go in with it.

## ponytail-review

What this change does: `gtd summary --slice` now goes through one call,
`summaryFor(run, sliceName)`, which loads the config once, replays only for a
named slice, and returns the prompt plus an optional version warning or
unknown-slice refusal. Replay refusals for `gtd slices`, `gtd summary --slice`
and `gtd history` now carry the version warning in their message. Load assumed:
one person running a read-only CLI command; no scale concern.

Traced: all `summaryFor` callers (only `runSummaryCommand`), `replayedSlices`
callers (`processSlices`, `locateSlice`), `replayFinishedProcess` callers
(`replayedSlices`, `historyTrail`). Every error `withWarning` rewraps is a plain
`Error` (`configRefusal`, `slicesDivergence`, `notClosedError`/`replayError`),
so rewrapping loses no type or exit code. Slice ranges come from `sliceRangesOf`
over the same `run`, so the removed `narrowToSlice` guard is unreachable. New
tests would fail with the guarded behaviour removed (warning on refusal, unknown
slice keeps warning, no-summary returns no prompt).

**Nice to have**

1. **`SummaryResult` is exported but nothing imports it**
   (`src/edge/Edge.ts:1491`)
   - **What this is:** The result type of `summaryFor`.
   - **Problem:** It is not re-exported from `src/edge/index.ts` and no other
     module names it; `Program.ts` destructures the value without the type.
   - **Fix:** Drop `export`. One word.
   - **If we skip it:** A stray public-looking type that suggests a contract
     nobody uses.

Verdict: Ship. Lean: -1 word possible.

## test-audit

Traced every new or changed test against the code it guards. Each one would fail
if its guard were removed:

- No summary template returns `{prompt: undefined}` before any replay. If the
  replay ran first, it would refuse on config drift.
- A plain call never replays. If it did, the edited config would refuse it.
- A named slice on an empty trace refuses with the full "HEAD neither closes"
  text.
- An unknown slice keeps the version warning. The feature's regex also checks
  that the warning prints before the refusal.
- `withWarning` is checked on both paths: config drift
  (`slices-command.feature`) and divergence (unit test).
- The new `restAt` cost test is the only check on `Rest.cost`. Before, nothing
  covered `total` or the order of `byModel`. That makes it the right guard for
  the `costTotals` extraction.
- The dropped "exact slice passed" assertion is still covered by the
  slice-resolution test.
- The removed `narrowToSlice` guard had no test, and it can no longer be
  reached.

No mocks supply the behaviour a test asserts, and no expected values are
generated by the code under test.

**Nit**

   just above it.** It repeats that test's config edit and its `readFileAtRef`

   (`src/edge/Edge.test.ts:931-959`, duplicating `:905-929`)
   - **Problem:** The two tests check one contract, the divergence refusal, with

## spec-challenge

Planning docs read: round 1 `REQUIREMENTS.md` (0aad07ae), `ARCHITECTURE.md`
(b4b6422e), packages 01/02 (d3f2a201); round 2 `REQUIREMENTS.md` (cabe6df6),
`ARCHITECTURE.md` (1533f740), package 01 (afe31a66). Checked each decision
against `docs/cli.md`, `renderFailure`, the `--json` envelope and the pinned
scenarios.

**Should fix**

1. **The round-2 spec accepts the warning folded into the refusal message. That
   breaks the stderr contract the round-1 spec and `docs/cli.md` rely on.**
   (round-2 REQUIREMENTS.md §1 "Assert presence, not line order — the refusal
   and warning share one error message today"; ARCHITECTURE.md 1533f740
   "Test-only change: the behaviour already ships";
   `src/edge/Edge.ts:1724-1733`)
   - **Decision:** keep `withWarning`, which appends `\ngtd: warning: …` to the
     `Error.message` of the config-edited and diverged refusals. Pin it by
     presence only, so the join is never challenged.
   - **Invariants it conflicts with:**
     - `docs/cli.md` L430-434 lists the WARNING as one of three things stderr
       carries "beyond the `gtd: ` message line". Now it is part of that
       message.
     - `docs/cli.md` "Error envelope": under `--json` the envelope is
       `{"state":"error","prompt":"<message>"}` (`src/cli/Cli.ts:1487`). So for
       `gtd slices --json`, a driver now gets the warning inside `prompt`, not
       as its own stderr line the way the success path prints it.
     - Round-1 spec concern 2 and its pinned `summary-slice.feature` scenario:
       on `gtd summary --slice`, the warning comes _before_ the refusal, printed
       by the CLI through `Narrator.warn` ("the edge never narrates … the CLI
       prints it"). The config-drift and diverged refusals of the same command
       now print it _after_, from inside the edge's error. One command now
       orders the warning two different ways, depending on which refusal fires.
     - `renderFailure` (`src/platform/Commentary.ts`) is how extra lines get
       attached to a failure: `GtdError.detail`, indented under the message and
       kept out of `prompt`. `withWarning` skips that path.
   - **Why it matters:** the round-2 scope was "test-only", so it pinned the
     join without questioning it. Telling a scenario not to check order is a
     sign the spec knew the output shape was off.
   - **Fix:** in `replayFinishedProcess`, stop rewriting the message. Return the
     warning beside the failure instead: either a `GtdError` with the warning in
     `detail` (this keeps `prompt` clean), or a tagged failure the CLI unwraps
     and passes to `Narrator.warn` before it fails. The second option gives
     every refusal the round-1 order. Then tighten the new
     `slices-command.feature` scenario to check that the warning comes first, as
     `summary-slice.feature` does. If the join stays, change `docs/cli.md` to
     say a refusal carries the warning in its message (and in the `--json`
     `prompt`).
   - **If we skip it:** drivers parsing the `--json` envelope get a two-line
     `prompt`, and the documented "separate WARNING line" holds only on success
     and the unknown-slice path.

Checked, no conflict: round 2 scoping out `gtd history show` contradicts no
test. Leaving the config edit uncommitted matches the copied scenario and the
edit check reading the working tree.
